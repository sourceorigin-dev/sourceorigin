# Write the documentation

**Scope.** Do only what this skill's task asks. No drive-by refactors, renames,
reformatting or extra features. Note anything else in your report or in an issue
instead of fixing it. Ask the owner before widening the change. Reread your diff
before handing back and drop every hunk the task doesn't need. See "Scope" in
`AGENTS.md`. Report only defects in the change and regressions it causes.
Anything else is a follow-up.

Read `docs/dev/documentation.md` in full before you write anything. It is the
documentation's writing guide, and everything below only points into it:

- **Where pages go:** the user guide (`docs/user`) or the contributor guide
  (`docs/dev`), and `docs/SUMMARY.md`, which lists every published page.
- **Writing and Style:** how to write a page, with an example, and the outline
  every feature guide in the user guide follows.
- **Screenshots:** they are generated by `just docs screenshots`, never taken
  by hand, through the specs in `tests/browser/screenshots/`.
- **Links:** how to link to pages, anchors and repository files.
- **Building and checking:** `just docs` builds the book and checks every link
  and anchor.

Check every claim against the code before you write it: the documentation
must say what auth does now. Before you finish, run `just docs`, and
`just docs screenshots` if you changed a page a screenshot shows. The `preview`
skill runs the app, to check that the pages, labels and commands you document
are right.
